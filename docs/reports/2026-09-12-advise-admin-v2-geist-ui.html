Confirmed advisory

Admin v2 Geist UI map

A scoped visual-migration decision for the existing Admin application. The static prototype supplies visual direction, while the current application remains the behavior source of truth.

Verdict

Proceed as a planned visual migration.

Apply a global Geist shell, a HomeBrief hybrid, and an isolated Đơn C presentation branch. Do not cook directly from the static mock because current shared selectors and SheetTab serve DTP, return tracking, and damaged-goods flows.

Verified evidence

  • 01

    CPC1HN Admin v2 Geist.dc.html contains the Admin v2 shell, #home, and a dedicated inline #donc mock.

  • 02

    CPC1HN Ops Home.dc.html provides the Home information architecture, but it uses the old warm and Inter visual system.

  • 03

    src/App.jsx owns universal .dashboard-* shell chrome for every route.

  • 04

    src/components/SheetTab.jsx is shared by Đơn C and DTP. Shared .sheet-tab-* and .report-* CSS is also consumed by return-tracking and damaged-goods surfaces.

Confirmed scope and non-goals

In scope

  1. Apply Admin v2 Geist shell chrome globally to all routes.
  2. Map HomeBrief with Ops Home information architecture and Admin v2 typography, surfaces, spacing, controls, and states.
  3. Map Giao hàng Đơn C with a Don-C-only presentation branch or namespace while retaining current data, actions, storage keys, and Supabase behavior.
  4. Keep DTP, return tracking, damaged goods, Tổng đơn, TMĐT, Nhập hàng, and other tab content designs unchanged.
  5. Add shadcn or 21st primitives only when a mock requires a missing primitive.
  6. Target 1440px fidelity and preserve existing mobile and tablet behavior without redesigning it.

Non-goals

  • Change business logic, data contracts, Supabase calls, report or export behavior, routes, or storage keys.
  • Redesign mobile, tablet, or a tab outside Shell, HomeBrief, and Đơn C.
  • Restyle generic .sheet-tab-* or .report-* selectors to achieve the Đơn C look.

Decision flow

Each decision narrows visual change to the smallest boundary that protects current behavior.

01

Prototype evidence

Inspect and annotate the Admin v2 shell, Ops Home information architecture, and inline #donc mock. Use the prototype as visual evidence, not as a workflow specification.

02

Global shell decision

Change .dashboard-* intentionally as a global shell migration. Every route inherits chrome, so navigation and layout smoke checks are required.

03

Home hybrid decision

Preserve Ops Home information architecture and channel derivation. Apply Admin v2 Geist typography, neutral surfaces, spacing, controls, and states without returning to warm Inter styling.

04

Don-C-only branch

Add a Đơn C root marker and scope every new selector beneath it. Branch or extract presentation only for type === 'donC'; retain the DTP path and shared report children.

05

Verification gates

Review, security and Snyk gates, browser checks at 1440px, npm test, and the production build validate the accepted implementation path.

06

Cursor audit

Stop after all verification gates and submit the completed migration for the Cursor audit. Do not extend scope during the audit handoff.

Benefits and trade-offs

Benefits

  • One coherent Geist shell while preserving existing operational behavior.
  • High-fidelity Đơn C without breaking DTP or other consumers of shared CSS.
  • Home retains established operations information architecture instead of adopting a static marketing-like mock blindly.

Trade-offs

  • A Don-C-specific presentation path is more code than CSS-only styling, but it is the smallest safe boundary for fidelity.
  • A global shell migration changes chrome on out-of-scope routes. Their content is protected, not their surrounding frame.
  • Static mocks do not specify dynamic states. Fidelity stops at visual composition, not invented workflow.

Work checklist

  • Inspect and annotate the Admin v2, Ops Home, and inline #donc prototype sections.
  • Plan global shell boundaries and every affected route smoke check.
  • Plan the HomeBrief information architecture and visual split while preserving channel derivation and navigation semantics.
  • Plan a Don-C-only root marker, scoped CSS, and presentation branch while retaining existing data and actions.
  • Implement only the planned Shell, HomeBrief, and Đơn C surfaces.
  • Verify the 1440px shell, HomeBrief, Đơn C, DTP, return tracking, and damaged goods surfaces in a real browser.
  • Run review, security and Snyk gates, npm test, and the production build. Stop for the Cursor audit.

Measurable success metrics

1440px fidelity

Shell, HomeBrief, and Đơn C match the specified Admin v2 visual source at 1440px without changing observed business behavior.

Protected content

DTP, return tracking, and damaged goods retain their content layout and controls under the new global shell.

Isolation

No source change touches Supabase calls, storage-key strings, report or export behavior, or shared generic SheetTab and report CSS for a Don-C-only visual goal.

Six-surface smoke

Browser smoke checks complete for shell, HomeBrief, Đơn C, DTP, return tracking, and damaged goods.

Quality gates

npm test and npm run build pass. Snyk Open Source and Snyk Code report no newly introduced issue.

Cursor audit

The intended finish line is a completed, verified visual migration handed to Cursor for audit. The audit should confirm scope discipline, shared-selector isolation, and behavior preservation rather than prompt more visual invention.
