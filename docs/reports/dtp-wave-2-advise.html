Confirmed advisory

Wave 2 DTP presentation

A narrow addition to the current vinh-phu Admin v2 change set that lets Đơn DTP share the Wave 1 Geist surface already present there.

Verdict

Proceed, but only in the current vinh-phu change set.

The scope is a one-file CSS refactor plus a one-line JSX change. The Wave 1 Đơn C composition is stable enough to reuse on vinh-phu, but it is not merged to master. DTP must remain in the same Cursor audit and merge cycle. The risk is accidental regression of Đơn C, Return, or Damaged, contained by preserving unscoped selectors and verifying the characterization suite plus browser smoke.

Confirmed requirements and goals

On vinh-phu, Đơn DTP remains on the old warm and cpc-blue surfaces while Đơn C uses Admin v2 Geist styling. Reviewers see two product tabs with visibly mismatched visual quality in the current Admin v2 change set.

  • 01

    src/components/SheetTab.jsx: Đơn C keeps .donc-v2 only. Đơn DTP adds .dtp-v2 only. No other type gets either class.

  • 02

    src/index.css: every existing .donc-v2 rule becomes a grouped selector. Root rules use .donc-v2, .dtp-v2; descendant rules preserve the full selector path, such as .donc-v2 .child, .dtp-v2 .child. Both types share declared values without copied blocks.

  • 03

    Return, Damaged, unscoped .sheet-tab-*, and .report-* CSS remain unchanged. Business logic, data contracts, Supabase calls, routes, and storage keys remain unchanged.

  • 04

    Verify SheetTab.characterization.test.jsx and browser smoke at 1440px for Đơn C, Đơn DTP, Return, and Damaged.

Combined-scope constraint

Admin v2 Geist Wave 1 exists on vinh-phu and feat/admin-v2-geist-ui-map, not on master. Keep DTP on vinh-phu; Cursor audits the combined scope before its single merge to master.

Non-goals

Do not redesign Return, Tổng đơn, Damaged, mobile, or unscoped CSS. Do not add components, shadcn primitives, or behavior changes.

Decision rationale

The composition mirrors the implementation boundary. The class is applied only at the shared root, then existing presentation values are reused through explicitly paired selectors.

Do and do not

Do

  1. Inspect the .donc-v2 block in index.css around lines 1883 to 2004 and after. List each unique root-level and descendant selector. Confirm the rules are presentational only.
  2. Change the root class expression from ${isDonC ? 'donc-v2' : ''} to ${isDonC ? 'donc-v2' : type === 'donDTP' ? 'dtp-v2' : ''}, or the equivalent that tests type === 'donC' first.
  3. Replace each root selector with .donc-v2, .dtp-v2. For each descendant, repeat the full path, such as .donc-v2 .sheet-tab-shell, .dtp-v2 .sheet-tab-shell.
  4. Run the characterization test and use browser smoke to confirm Đơn C is unchanged, Đơn DTP matches it, and Return and Damaged are unchanged.
  5. Hand off the combined Admin v2 scope to Cursor for review and Snyk audit before the single merge from vinh-phu to master.

Do not

  • Do not use ${isDonC ? 'donc-v2' : 'dtp-v2'}. It gives every non-Đơn C type the DTP class, including TMĐT, Tổng đơn, and Nhập hàng.
  • Do not append a bare , .dtp-v2 to a descendant selector. .donc-v2 .sheet-tab-shell, .dtp-v2 loses the descendant relationship.
  • Do not copy .donc-v2 blocks into new .dtp-v2 blocks. Grouped selectors share declarations without doubling maintenance.
  • Do not add .dtp-v2 inside SheetTab beyond the root. Descendant styling comes from the grouped root selectors.
  • Do not alter ThongKeGiaoHang, ThongKeDoiTac, DataTable, SheetReportPanel, or useSheetReportActions. They are outside the confirmed presentation-only scope.
  • Do not refactor or clean up adjacent unscoped .sheet-tab-* rules while making this presentation-only change.

Alternatives, deferred

These options could be worthwhile only if the pattern expands. They are not requirements for this wave.

CSS custom properties

Shared tokens such as --v2-surface-bg could avoid selector edits. This is a larger refactor, so note it only if the pattern spreads.

Shared admin utility

A higher-level .admin-v2 class could replace both names, but it requires checking every consumer and is premature before a third tab adopts the look.

CSS rule grouping

Grouping structural rules before visual overrides could ease future additions. It is a refactor, not part of the present requirement.

Benefits and trade-offs

Benefits

  • Đơn C and Đơn DTP show one consistent Admin v2 Geist look immediately.
  • Each existing .donc-v2 rule changes once into a grouped form, making the diff straightforward to audit.
  • Return, Damaged, and other surfaces remain protected because unscoped selectors are untouched.
  • The existing .donc-v2 composition is already implemented and locally verifiable on the current Admin v2 branch. DTP reuses its declared values unchanged.

Trade-offs

  • Two class names still express the same visual intent. A shared class becomes worthwhile if a third tab adopts the look.
  • Đơn C and DTP remain coupled until the Admin v2 work reaches master. Any Wave 1 change before Cursor audit must be reviewed against DTP too, so both changes share one audit and merge cycle.
  • The characterization tests run in Node, not a browser. The 1440px visual check remains manual until visual regression exists in CI.
  • Proceed with grouped selectors only while DTP remains in the same vinh-phu change set. If it moves to another branch or Wave 1 changes materially, re-check the composition and merge plan first.

Implementation checklist

  • □List every .donc-v2 selector in index.css. Distinguish root-level from descendant rules and confirm all are presentational.
  • □In SheetTab.jsx, apply .donc-v2 only for Đơn C and .dtp-v2 only when type === 'donDTP'. Confirm TMDT, Tổng đơn, and other types receive neither class.
  • □Replace each root .donc-v2 rule with .donc-v2, .dtp-v2. Preserve each descendant selector path by adding the equivalent .dtp-v2 .child sibling. Add no blocks and delete no rules.
  • □Run SheetTab.characterization.test.jsx. Both DonC and DonDTP suites must pass.
  • □At 1440px, smoke Đơn C, Đơn DTP, Return, and Damaged. Confirm TMĐT and Tổng đơn are classless and visually unchanged.
  • □Run npm run build and require a clean build.
  • □Hand off the combined Admin v2 scope to Cursor for review and Snyk scan before the single vinh-phu to master merge.
